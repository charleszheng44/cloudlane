It does not change persistent compositor configuration. [Hyprland dispatcher contract](https://wiki.hypr.land/configuring/core/dispatchers/).

Fixes caught by testing included Qt sequence conversion into JavaScript arrays, a nullable SQLite error field, and invalid absent metadata values sent over D-Bus. The last issue aborted the isolated MPRIS test; the coredump identified MprisPlayer::changed → QtDBus/libdbus marshalling. Metadata now uses valid typed strings and the same regression test passes. No user account or music data was involved in that test.

The graphics driver probe prints `Cannot load libcuda.so.1` on this machine, then succeeds with the available graphics stack. This was not a playback or rendering failure.

## Desktop player and layout

The desktop arrangement uses [Spotify's documented library / central browsing / Now Playing layout](https://newsroom.spotify.com/2023-06-20/spotify-desktop-experience-redesign-your-library-now-playing-views-customize/) as a visual reference. It retains the active Omarchy palette and system font. Original vector icons render through the system Qt Quick Shapes module; no icon font or web runtime is required.

The player keeps artwork and track information on the left, transport controls in the center, and volume/panel controls on the right. Progress stays beneath the transport at desktop widths. The volume slider remains visible at the minimum supported width. Mute preserves the last audible level within the window; controls have accessible names, keyboard focus and tooltips. Sidebar playlists use the logged-in account's existing playlist endpoint and are cleared on logout. Short windows use compact browsing rows so artwork does not hide titles.

The native click test caught a real next/previous issue: stopping a track set the client's cached pause flag, but starting another unpaused track could leave mpv's pause property unchanged, producing no notification. `Backend::load` now initializes the cached flag from the requested playback state. The regression test switches between two entries backed by a local media fixture and verifies playback resumes.

## Account login recovery

The phone approved the consumer QR login, but the original QML poll remained at the scanned state. Moving polling to a worker-owned Qt timer removes its dependency on the QML animation clock. A later run encountered an unrecognized service status after scanning; the client previously stopped immediately. The numeric status was not retained, so its exact cause is unconfirmed.

A native request using the same approved QR reference in a fresh session returned 803. The account was verified and its cookies saved through Secret Service before exiting. A separate process then restored the saved account successfully: 7 playlists, 24 daily recommendations, and one full-track playback grant (code 200, no trial). The installed app also emitted the authenticated state after restart. No further phone scan was needed for this recovery.

QR requests now omit existing account/anonymous cookies, while retaining response cookies for account verification. Qt Network uses the explicitly constructed cookie header. This matches the successful fresh-session request; cookie interference remains an inference rather than a captured server diagnosis. Unexpected QR statuses receive bounded retries without discarding the current QR reference; diagnostics record only the numeric code and login phase. Account synchronization can be retried with the existing grant. Session persistence completes before the UI receives account confirmation.

## Not proven

Real-account checks above cover saved login restoration, playlist listing, daily recommendations and one playback grant. They do not establish all library payloads, actual decoding of that online stream, download grants, writes, cloud or subscription operations. Download tests prove the local download engine, not NetEase account rights. Native video tests prove rendering of a local video, not availability of a particular online MV.

Large-font accessibility, protected offline media, Together, cloud upload, creator publishing and other outstanding parity work remain in [IMPLEMENTATION.md](../IMPLEMENTATION.md). This build is a development preview.
